# Release 1 limitations

- Windows x64 is the verified platform. macOS, Linux and Windows ARM64 have not been release-tested.
- Build using Node 24 (pinned `.node-version`) and pnpm 11.25.0. The portable app needs no separate Electron installation. Run commands use installed host runtimes: Node 22.18+ for TypeScript type stripping, Node for JS, Python for `.py`, and Git for source-control status.
- Opening is limited to 1 MiB of valid UTF-8. Binary and larger files are refused without changes. Existing in-memory work can still be saved even if an edit grows past the opening limit. Avoid pasting very large content: the native textarea and full-text services retain whole strings.
- Undo has at most 500 transactions and also a 32 MiB text-cost / 100,000 history-piece budget. Large or fragmented edits shorten history. The original buffer stays for the lifetime of a document; additions are compacted periodically. Undo history is not restored after restart.
- Native textarea editing handles normal IME input and selection. Automated coverage includes a composition-event sequence and surrogate-pair deletion; physical input-method keyboards, bidirectional text layout, grapheme navigation across complex emoji/combining sequences and full screen-reader workflows have not been exhaustively tested. Custom multi-cursor deletion protects surrogate pairs but is not a complete Unicode grapheme-layout engine.
- Saves use a temporary file in the same directory followed by rename, with expected disk-hash checks and serialized writes. No file or directory fsync is performed, so power-loss/crash durability is not guaranteed. An unrelated writer can still race the final hash-check/rename window; filesystem APIs do not provide a cross-process compare-and-swap here. Watchers/conflict prompts protect ordinary external edits; this is not a multi-process file lock.
- Recovery is local browser storage with a 400 ms debounce, not an acknowledged durable journal. Quota/persistence failures display a persistent warning; save to disk. Recovery can lose the most recent debounce interval after abrupt termination. A valid stored snapshot is restored even when the file was deleted. Malformed recovery storage is not repaired automatically.
- LSP is bundled `typescript-language-server` with TypeScript. Server diagnostics can lag typing, and that server does not publish document versions for every diagnostic; obsolete workspaces and closed paths are ignored. Go-to-definition is limited by authorized filesystem paths. An unavailable server is shown as offline; reopening the workspace restarts it. Arbitrary server configuration is future work.
- Search is literal, bounded to 12,000 enumerated files, 1 MiB per file and 500 matching lines. Dependency/generated directories and symlink entries are excluded. It does not implement regex or an incremental search index.
- PTY processes run with the user's local permissions. Normal window/app exit and workspace-switch cleanup are tested. Abrupt host/OS termination cannot be guaranteed to clean up unrelated descendants.
- Automated dialog choices are controlled in regression tests. The normal native dialogs remain in the app. The desktop evidence uses real Electron, LSP, filesystem, Git and PTYs; selected IPC replies and storage writes are delayed/failed only to reproduce races.
- Electron, xterm.js, node-pty, chokidar, TypeScript, the language server, vscode-jsonrpc, Vite/esbuild and Electron Packager are integrated libraries. The piece table, transaction/history logic, tokenizer, textarea editor coordination, workbench UI and integration orchestration are custom code. This is not a custom terminal emulator, TypeScript compiler or language server.
- The portable folder is unsigned. Keep all its resources beside `Orbit.exe`. Publishing/signing/installer distribution is separate from preparing this local candidate.
- DAP/debugger, plugins, arbitrary LSP configuration, Tree-sitter and a fully custom layout engine remain future work.
